# One-Mac Benchmark Runbook

This runbook is the first evidence path for AkiDB's Mac-first product claim.
It measures the current single-node standalone server on a clean local data
directory and writes a JSON artifact suitable for benchmark reports.

The benchmark is synthetic. It proves local throughput and latency shape; it
does not prove semantic retrieval quality. Run the quality gates in
[vector-quality.md](vector-quality.md) for recall, nDCG, MRR, and semantic
retrieval checks.

## Default Smoke Benchmark

```bash
./scripts/benchmark-one-mac.sh
```

Defaults:

- `DIMENSIONS=768`
- `VECTORS=100000`
- `QUERIES=1000`
- `BATCH_SIZE=1000`
- `TOP_K=10`
- `NPROBE=64`
- `CONCURRENCY=1`
- `SLO_MS=50`

Results are written to `benchmark-results/one-mac-*.json`.

## Reference Workload

Use the product reference shape when the Mac has enough memory:

```bash
VECTORS=1000000 \
DIMENSIONS=768 \
QUERIES=5000 \
BATCH_SIZE=1000 \
CONCURRENCY=1 \
./scripts/benchmark-one-mac.sh
```

For 1536-dimensional embeddings:

```bash
VECTORS=1000000 \
DIMENSIONS=1536 \
QUERIES=5000 \
BATCH_SIZE=500 \
CONCURRENCY=1 \
./scripts/benchmark-one-mac.sh
```

## Concurrency Sweep

Run separate artifacts for each concurrency level instead of mixing results:

```bash
for c in 1 2 4 8 16; do
  CONCURRENCY="$c" VECTORS=1000000 QUERIES=5000 ./scripts/benchmark-one-mac.sh
done
```

## Artifact Requirements

Every published one-Mac benchmark should include:

- The JSON artifact generated by `akidb-bench --output-json`.
- The exact AkiDB commit SHA from the artifact.
- Mac model, macOS version, architecture, and memory from the artifact.
- Dataset dimensions, vector count, topK, `nprobe`, query count, and
  concurrency.
- Insert throughput, search QPS, and P50/P95/P99 latency.
- A separate vector-quality artifact for recall-oriented claims.

## Interpreting Results

The README target is P95 search latency under 50 ms for `D=768`, `N=1M`,
`topK=10`. Treat a passing small smoke benchmark as a development signal only.
Do not use it as product proof.

For a release claim, the benchmark should be run on a documented reference Mac
SKU with the reference workload and checked into a dated report under `docs/`.
